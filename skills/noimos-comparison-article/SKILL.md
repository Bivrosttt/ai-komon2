# Noimos比較記事

読者が別タブで再調査しなくても候補を選べる、実在サービスの比較レビューを作る。比較記事は「調べ方の宿題」ではなく、調査結果と判断を渡すページにする。

## 全工程チェックリスト運用（必須）

- [ ] 作業開始時に対象記事ごとの永続TODO（`docs/.../COMPARISON-REWRITE-TODO-YYYY-MM-DD.md`）を作成する。
- [ ] 調査・執筆・画像取得・検証・公開準備の全項目を `[ ]` / `[x]` のチェックボックスでTODOへ記録する。
- [ ] 各項目に証拠ファイル、出典URL、取得日、実行コマンド、または画面確認結果を紐づける。
- [ ] 証拠がそろうまで項目を `[ ]` のままにし、口頭の完了報告だけで `[x]` にしない。
- [ ] ブロッカー、代替ソース、公開情報では算定不能な項目、未完了項目をTODOに残す。
- [ ] 記事ごとにブリーフ、リサーチ、claim ledger、本文、価格入力、ホーム画面台帳、バリデーション、品質レポートのチェック欄を持つ。
- [ ] 最終報告ではTODOの未完了数と、各完了項目の証跡を照合してから完了と伝える。

## 絶対ルール

- [ ] 公式サイト、公式料金ページ、公式ヘルプを各サービスごとに調査する。
- [ ] 各サービスの公式ホーム画面をブラウザでスクリーンショットし、記事のサービス節の先頭（サービス見出しの直前）に置く。取得元URLと取得日をfigcaptionへ残す。
- [ ] ホーム画面へアクセスできない場合は、同じサービスの公式Docs・公式プロダクト画面にあるホーム画面画像を代替にし、「公式Docs掲載画面」と明示する。Cloudflareのブロック画面、ログイン画面、第三者サイトのスクリーンショットは成果物に使わない。
- [ ] 日本語の口コミ・レビューと海外の独立レビューを各サービスごとに調査する。G2、Capterra、Trustpilot、Reddit、国内レビュー媒体など、アクセス可能で出典を示せるものを使う。
- [ ] 料金を必ず比較する。プラン名、請求単位、掲載価格、通貨、無料枠、usage（分数・クレジット・生成数・席数・文字数など）を同じ表に載せる。
- [ ] usageが料金を左右するサービスは、料金だけでなく単位あたりの実効コストまたは比較シナリオを計算する。計算不能なら「公開情報では算定不能」と明記し、逃げない。
- [ ] 強み・弱みを全候補で同じ項目にそろえた表を必ず置く。
- [ ] 本文でサービス名が初めて出る箇所は、そのサービスの公式サイトへのリンクにする。見出し、結論、比較表、本文のどこが初出かをDOM順で確認する。以後の同名は必要に応じてリンクを省略する。
- [ ] サービス名・H1・結論・比較表の主リンクは、必ずそのサービスの公式ホーム（または公式プロダクトホーム）へ向ける。`/pricing`、`/plans`、課金画面をサービス導線に使わない。
- [ ] 料金ページへのリンクは価格セルまたは調査ソース欄に限定し、リンク文言を「料金」「Pricing」など価格ソースと明示する。サービス名のホームリンクと混同させない。
- [ ] 読者向け本文では調査結果を断定的に示し、最後の一箇所だけAI顧問室へ接続する。比較本文の途中に自社導入の営業文を挟まない。
- [ ] 価格・usage・口コミには取得日を付ける。変動情報は「2026年7月31日時点」のように記事内で明示し、読者へ再調査を押し付ける一般的な注意書きで代用しない。

## 明確に禁止する書き方

以下を比較記事の本文・表・CTAに書かない。読者が比較サイトへ来た目的を失わせる予防線・社内宿題である。

- [ ] 「同じ台本・素材・尺で試す」「生成時間、修正回数、権利確認、公開までの工数を記録する」など、比較を読者へやらせる文を入れない。
- [ ] 「誰が止めるか」「社内で確認する担当を決める」「社内ルールを作る」など、サービス比較から逸れた社内運用チェックリストを入れない。
- [ ] 「公式サイトで確認してください」「契約前に料金を再確認」「対象プランを確認」など、記事側のリサーチ不足を読者へ返す文を入れない。
- [ ] 「料金は変わるので比較できない」として、価格・usage・コスパを空欄にしない。
- [ ] 「最適解は用途で変わる」だけで結論を避けない。用途ごとの第一候補と、選ばない条件まで書く。
- [ ] 比較表の直前・直後に、一般論の免責、担当者・承認・権限の宿題、曖昧な「まず試す」を置かない。

- [ ] 禁止語の検査対象例：`同じ台本`、`同じ素材`、`同じ尺`、`生成時間`、`修正回数`、`権利確認`、`公開までの工数`、`誰が止める`、`社内で`、`確認してください`、`公式ページを再確認`、`対象プランを確認`、`契約前`、`初回は`。

## 実行手順

### 1. 比較ブリーフとTODO

- [ ] 主キーワード、検索意図、読者、候補サービス、比較シナリオ、CTA、更新日をTODOに固定する。
- [ ] 候補は知名度だけでなく、読者の代替候補になる実在サービスを3〜6個選ぶ。
- [ ] 各候補の公式URL、料金URL、usage仕様URL、国内口コミURL、海外口コミURLを調査表に記録する。
- [ ] 各候補のホームURL、スクリーンショットファイル、取得日、代替画面かどうかをスクリーンショット台帳に記録する。

### 2. 深掘り調査

- [ ] 公式プロダクトページで、対象業務、主要機能、入力、出力、連携、提供地域を確認する。
- [ ] 公式料金ページで、無料枠、有料プラン、請求単位、usage上限、超過課金、チーム機能を確認する。
- [ ] 日本語口コミから、良い点・不満・サポート・日本語品質・料金への反応を抽出する。
- [ ] 海外口コミから、実運用上の強み・弱み・障害・学習コスト・課金への反応を抽出する。
- [ ] 口コミは単発の感想を事実扱いしない。同じ傾向が複数件に出る場合だけ「レビューで目立つ傾向」として書く。
- [ ] 取得日、出典URL、主張、証拠種別、確度をclaim ledgerへ保存する。

### 3. 価格・usage・コスパ

- [ ] 全候補で同じ通貨・請求周期へそろえる。通貨換算は換算日とレートの出典を記録する。
- [ ] 代表シナリオを一つ定義する（例：月10本、月20時間、月5席）。そのシナリオで月額、含まれるusage、超過時の扱いを表にする。
- [ ] `コスパ = 代表シナリオで得られる成果物 / 実効月額` のように、読者が理解できる単位で計算する。
- [ ] usage制限が品質・速度・機能差を生む場合、価格表の隣で説明する。
- [ ] 実効コストを計算できない場合は、欠損理由を調査メモに残し、記事では「公開情報では算定不能」と明示する。空欄や「要確認」で終わらせない。

### 4. 記事構成

- [ ] H1で対象、比較意図、更新年を明示する。
- [ ] 記事公開時点で共通ヘッダー（ブランド、主要導線、相談CTA）を実装し、「ヘッダーは後で追加する」状態で完了扱いにしない。
- [ ] デスクトップでは左目次・中央本文・右CTAを固定幅の3カラムで配置し、左右欄が本文に押し潰されないことを確認する。モバイルでは目次を隠し、CTAを記事下へ移す。
- [ ] 右CTAは本文を圧迫しない最低270px程度の幅を確保し、見出し・説明・ボタンを短い単位に整理する。見出しは必要に応じて意図的に改行し、デスクトップのボタン文言は1行で読める長さにする。
- [ ] 冒頭の`.answer`で用途別の第一候補と結論を出す。
- [ ] 冒頭の`.key-points`だけで、本文を読まなくても用途別の第一候補、価格・usageの目安、選ばない条件が分かるように書く。
- [ ] `.key-points`に「月額だけでなく比較します」「レビューを記載します」のような記事構成の説明を置かず、サービス名・具体的な数値・判断理由を置く。
- [ ] 早い位置に「料金・usage・コスパ比較表」を置く。
- [ ] その後に、サービスごとの短いレビュー（向く読者、強み、弱み、口コミ傾向、価格の意味）を書く。
- [ ] 各サービスレビューの見出し直前に公式ホーム画面のスクリーンショットと出典figcaptionを置く。
- [ ] 「強み・弱み比較表」を置き、同じ評価軸で横並びにする。
- [ ] 各サービスの初出名を公式リンクにする。表のサービス名を初出にする場合はそこでリンクする。
- [ ] 読者が選べる決定ルール（「AならX、BならY」）を書く。
- [ ] FAQ、公式ソース、口コミソース、取得日を置く。
- [ ] 最後にだけ、比較結果を自社業務へ組み込むAI顧問室CTAを置く。CTAは「最短経路」と「無料でコンサル一回分をプレゼント」を使用する。

### 5. 品質ゲート

- [ ] 比較専用バリデータで、禁止文、価格表、usage、コスパ、強み弱み、初出リンク、CTAを検査する。
- [ ] 比較専用バリデータで、初出のサービスリンクが登録した公式ホームURLと一致し、`pricing` / `plans` URLへ飛ばないことを検査する。
- [ ] 比較専用バリデータで、サービス数とホーム画面スクリーンショット数が一致し、各レビュー見出しの直前に画像があることを検査する。
- [ ] Noimos SEO/GEO validator、content quality gateを実行する。
- [ ] デスクトップ、タブレット、スマホで比較表の可読性とCTAを確認する。
- [ ] デスクトップ、タブレット、スマホでヘッダー、左右欄、中央本文の幅と横スクロールを確認する。
- [ ] 公式リンク、口コミリンク、JSON-LD、画像、内部リンク、横スクロールを確認する。
- [ ] `初回は`、`同じ台本`、`確認してください`などの禁止語をリポジトリ内の対象記事から検索し、0件にする。

## 必須成果物

- [ ] `*-brief.md`：検索意図、候補、代表シナリオ、決定ルール。
- [ ] `*-research.md`：公式・国内口コミ・海外口コミの調査表と取得日。
- [ ] `*-claims.json`：claim、source_url、publisher、retrieved_at、evidence_type、verified。
- [ ] `*-content.md`：記事本文の根拠付きスナップショット。
- [ ] `*-pricing.csv`：候補別の価格、usage、コスパ計算の入力。
- [ ] `home-screens/`：候補サービスの公式ホーム画面スクリーンショット。
- [ ] `*-screenshots.json`：スクリーンショットURL、取得日、代替画面の理由。
- [ ] `*-validation.json`：SEO/GEO validatorと比較専用バリデータの結果。
- [ ] `*-quality-report.json`：AI専用または設定済み承認モードの品質結果。
