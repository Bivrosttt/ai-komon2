# LP作成・公開チェックリスト

LPを作るときは、ページを完成させるだけでなく、広告クリック後の計測・CTA遷移・実表示まで確認してから公開する。

## 1. 企画・訴求

- [ ] 対象業種・役職・業務シーンを1文で説明できる
- [ ] クリエイティブからLPへ、課題・業務・提供価値の流れがつながっている
- [ ] 「AIで何を作るか」ではなく「どの業務をどう整理・改善するか」が伝わる
- [ ] 申し込みの提供物（例：コンサル1回分）と、申し込み後の流れが明確
- [ ] 無料にする理由、担当者の経歴、実績、契約の有無を説明して不安を解消している
- [ ] 過度な成果保証・緊急性を煽る表現・根拠のない数字を使っていない

## 2. ファーストビュー

- [ ] 画面を開いた瞬間に「誰向け」「何をする」「次に何をする」が分かる
- [ ] 見出しは短く、最重要メッセージが1つに絞られている
- [ ] 業種名・提供価値・CTAがファーストビュー内に収まっている
- [ ] CTA文言が具体的で、ページ内の他のCTAと完全に一致している
- [ ] クリエイティブとLPのトンマナ（色・写真・言葉・温度感）が一貫している
- [ ] ファーストビューの画像が業種・業務シーンと一致している
- [ ] 文字が画像に埋め込まれておらず、読み上げ・検索・計測可能なHTMLになっている

## 3. 本文・信頼構築

- [ ] 具体的な業務例を複数提示している（1つの課題だけに見えない）
- [ ] AIに任せる部分と、人が判断する部分を分けて説明している
- [ ] コンサル・支援の進め方が順番で分かる
- [ ] 担当者情報、経歴、実績、対応範囲が確認できる
- [ ] FAQで「AIに詳しくない」「準備物」「契約」「費用」の不安に答えている
- [ ] 業種別の例と、全般的な相談ができることのバランスが取れている

## 4. CTA・遷移

- [ ] ヘッダー、ファーストビュー、本文末尾の全CTAを確認した
- [ ] すべてのCTAが想定したフォーム・予約ページ・`#contact`へ遷移する
- [ ] CTAクリック後のURLに必要な `from` / UTM / クリックIDが引き継がれる
- [ ] 業種・キャンペーンを識別する値がページごとに重複していない
- [ ] 外部予約ページへ遷移する場合、実際のリンク先・表示内容・戻り導線を確認した
- [ ] CTAが無効、空リンク、古いLP、削除済みページを指していない

## 5. 計測・ヒートマップ

- [ ] GA4 / Meta Pixel / イベント計測の共通スクリプトが正しい順番で読み込まれている
- [ ] Microsoft Clarity の Project ID が設定され、対象LPの本番ホストでClarityタグが読み込まれる
- [ ] Clarityのセッション録画・ヒートマップで対象ページのパスを識別できる
- [ ] ページ表示、CTAクリック、フォーム到達、予約完了などの主要イベントを定義している
- [ ] UTM、`from`、`fbclid`、`gclid`の保持と、CTA先への引き継ぎを確認した
- [ ] ローカル確認では本番ホスト判定によって計測が抑止されることを理解し、本番でも確認した
- [ ] APIトークン・計測用Secret・個人情報をHTML、ログ、コミットに含めていない

## 6. レスポンシブ・アクセシビリティ

- [ ] 1440px、749px、390pxでファーストビューを実表示確認した
- [ ] `scrollWidth === clientWidth` で横スクロールがない
- [ ] 見出しの改行、CTAの折返し、画像の縦横比を確認した
- [ ] 画像の `alt`、見出し階層、リンク名、キーボード操作を確認した
- [ ] 画像読み込み失敗時にもCTAと主要コピーが読める
- [ ] スマホで画像・CTAが画面外にはみ出さない

## 7. リリース前の実行確認

- [ ] `node --check` またはプロジェクトの静的チェックが通る
- [ ] `git diff --check` が通る
- [ ] ブラウザのコンソールエラーがない
- [ ] 実際のブラウザで各CTAを確認した
- [ ] 最新LPの保存場所・旧LP・アーカイブの区分をREADMEまたはLP一覧に反映した
- [ ] 削除・移動したLPへの内部リンクが残っていない
- [ ] 本番公開後にページ表示、CTA、GA4、Clarity、Meta計測を再確認する
